# 01. 要件定義

> **v1 のスコープと、削った機能の理由は [README](./README.md) を参照。** 本書では各要件に `【v1】` / `【将来】` を付す。

## 0. 前提

| 項目 | 内容 |
|---|---|
| 目的 | **個人利用 + ポートフォリオ**。「AI/LLM 応用ができるバックエンドエンジニア」であることを示す |
| 利用者 | **開発者本人1人**（Basic 認証、公開 URL は出さない） |
| 体制 | 1人開発。**Spring 以外は未経験**（React / TypeScript / Next.js / プロンプト / インフラ） |
| 予算 | 実装 48〜70時間。ランニング **月 $10〜20**（生成コスト）+ インフラ実費 |
| 中核 | **アバターが動画で煽る**こと。映像は装飾ではなくプロダクトの本体 |

**「怒りが行動を生むか」という最大の前提は、開発者本人が数日間かけて生成 AI に煽られる実験を行い、効果があることを実測済み**である。よって本プロダクトは「仮説の検証」ではなく「検証済みの体験を自分の手で実装する」ものとして扱う。

## 1. プロダクトコンセプト

### 1.1 一言で

**「アバターに煽られて、ムカついて、やり返すために目標を達成する」習慣化アプリ。**

### 1.2 解決したい課題

目標を立てても続かない理由の多くは「今日サボっても誰も困らない」こと。従来の習慣化アプリは *褒める / 記録する / 通知する* で解決しようとするが、褒められることに慣れると効かなくなる。

本プロダクトは**負の感情（反発心・見返してやる気持ち）を燃料にする**アプローチをとる。「お前には無理」と言われたときに湧く反発心（心理的リアクタンス）を、意図的に、安全な形で設計に組み込む。

### 1.3 なぜ「テキスト」ではなく「動画」なのか

**煽りはテキストでも成立するが、体験の強度が違う。** 文字で読む「どうせ続かない」と、キャラクターが声と表情で言ってくる「どうせ続かない」では、反発心の湧き方が変わる。Q8 の判断はここに基づく。

同時に、この選択が**待ち時間**という技術的課題を生む。動画生成は数十秒〜数分かかる。本設計はこの待ち時間を隠すのではなく、**体験に組み込む**（§3.2）。

### 1.4 なぜ怒りが機能するのか / どこが危ういのか

| 機能する条件 | 破綻する条件 |
|---|---|
| 煽りの対象が**行動**（サボった事実）に限定されている | 煽りが**人格・容姿・出自**に及ぶ |
| 「やり返せる」出口がある（達成 → アバターが負けを認める） | 煽られっぱなしで報われない |
| ユーザーが煽りの強さを**自分で選べる** | 強度が固定で、逃げ場がない |
| ユーザーが「これはゲームだ」と認識できている | 本当に落ち込んでいるときに追い打ちされる |

**この設計は「怒りを利用する」以上、ユーザーを傷つける失敗モードを構造的に持つ。** 利用者が本人1人であっても、以下を機能要件と同格の必須要件として扱う（詳細は [05. 外部 AI 連携設計](./05-llm-design.md) §5 安全設計）:

- 煽り強度をいつでも下げられる／即座に止められる（**セーフティスイッチ**）【v1】
- 人格否定・容姿・出自・病気・自傷を煽りの対象から除外する（**NG ライン**）【v1】
- ユーザー入力に深刻な落ち込みや自傷の兆候を検知したら、煽りを止めて支援リソースを表示する（**セーフモード**）【v1】
- 達成時に必ず「アバターが負けを認める」報酬を返す（**カタルシスの保証**）【v1・テキストのみ / 動画版は将来】

> **自分1人用でも安全機構を削らない理由**: 安全設計はユーザー保護のためだけでなく、**「LLM を製品に組み込むときに何を考えるか」を示すポートフォリオの一部**でもある。三層防御の実装はコード量に対して情報量が大きい。

## 2. ターゲットユーザー

### 【v1】主要ペルソナ: 開発者本人

- 目標を立てては続かない自覚がある
- 生成 AI に煽られると実際に着手する（実測済み）
- 煽られた直後 30分以内の行動率が上がることを、自分の体感として確認している

### 【将来】想定ペルソナ

| ペルソナ | 特徴 | 刺さるポイント |
|---|---|---|
| 「宣言だけして終わる人」 | 20〜30代、資格勉強・ダイエット・副業などを始めては 2週間で止める | 「どうせ今回も三日坊主でしょ」と言われると意地でも続けたくなる |
| 「締切がないと動けない人」 | フリーランス／学生。締切があるときのパフォーマンスは高い | 外部から圧をかけられる状況を自分で作りたい |

### 対象外（明示的に除外）

- 現在メンタルヘルスの不調を抱えている人 → セーフモードへ誘導
- 未成年（18歳以上を対象とする）

## 3. コアループ

### 3.1 【v1】のループ

```
   ┌───────────────────────────────────────────────┐
   │                                               │
   ▼                                               │
[目標を宣言] ──▶ [アバターが煽る] ──▶ [ムカつく] ─┐│
   (Goal)         (動画で届く)       (怒りゲージ↑)││
                                                  ▼│
                                          [行動する]│
                                                  ││
   ┌─────────────────── [進捗を報告] ─────────────┘│
   │                     (ProgressLog)              │
   ▼                                                │
[アバターが煽る] ──────────────────────────────────┘
   │
   │ 目標達成
   ▼
[アバターが渋々認める（テキスト）] ──▶ 怒りゲージが 0 に落ちる演出
```

**設計上の要点**: ループの終端に必ず「勝ち」がある。煽り → 行動 → 煽り返し、で終わらせない。

**v1 では達成時の「掌返し」をテキストで返す。** 動画にすると1体験あたりの生成が2本になり、Q12 のコスト枠が半分になるため。**カタルシスの保証という安全要件は、テキストでも満たされる**（アバターが負けを認める文章は必ず返る）。

### 3.2 【v1】待ち時間の体験設計 ★中核

動画生成は数十秒〜数分かかる。この待ちを**隠すのではなく、煽りの構造として使う**。

```
t=0     投稿
t≈2s    煽り文が表示される            ← ここで即座に刺さる
t≈5-10s 音声が再生される              ← 声で追い打ち
t≈30s-  動画に差し替わる              ← 本人が出てきてもう一度刺す
```

**2段構えの方が煽りとして強い。** 文字で刺されて、しばらくしてから本人が出てきて刺し直す。しかも「着手し始めた頃に動画が届く」ため、行動のタイミングとも噛み合う。

一定時間（既定 3分）内に動画が届かなければポーリングを打ち切り、**完成した動画は履歴に現れる**（[06](./06-frontend-design.md) §3）。ページを離れても生成は止まらない。

## 5. 非機能要件

> **規模の前提が変わった。** 旧版の「DAU 1,000」は将来構想であり、**v1 の目標値ではない**。v1 の同時利用者は1人である。

### 5.1 【v1】の非機能要件

| 分類 | 要件 |
|---|---|
| **性能（テキスト）** | 煽り文の表示まで **p95 4秒**。ここは同期で返す |
| **性能（音声）** | 投稿から **10秒以内**に再生可能。VOICEVOX はローカルネットワーク内なので LLM より速い |
| **性能（映像）** | 投稿から **3分以内**を目標（**P0 で実測して確定する**）。超過時はポーリングを打ち切り、完成後は履歴に出す |
| **性能（その他 API）** | p95 300ms |
| **可用性** | ベストエフォート。**各段が個別に失敗しても、上流までの成果物は必ずユーザーに届く**（テキストだけ届く / 音声まで届く、という縮退が正常系） |
| **スケール** | 同時1ユーザー。**1日 3〜5本**の生成 |
| **コスト** | 生成コスト **月 $10〜20**。日次上限到達で自動的にテキストのみへ縮退。上限は環境変数で設定 |
| **耐久性** | **生成中のジョブはプロセス再起動をまたいで再開する。** 課金済みの外部 API 呼び出しを取りこぼさない |
| **保存** | 生成した音声・動画は Cloudflare R2 に永続保存。**Hedra の `download_url` に依存しない** |
| **セキュリティ** | Basic 認証 + HTTPS。**API キー（Anthropic / OpenAI / Hedra / R2）はバックエンドのみが保持**し、フロントに絶対に出さない |
| **プライバシー** | 進捗テキストは機微情報として扱う。LLM への送信は必要最小限。学習利用オフの設定を必須とする |
| **安全性** | §1.4 の 4要件（セーフティスイッチ / NG ライン / セーフモード / カタルシス保証）を満たす |
| **アクセシビリティ** | 動画には常にテキストが併記される（動画が届かなくても情報は完全）。`prefers-reduced-motion` を尊重 |
| **国際化** | 日本語のみ。VOICEVOX が日本語専用であるため、多言語化は音声・映像の設計から見直しになる |
| **ブラウザ** | Chrome / Safari の最新版。`<video>` の自動再生制約に注意（ミュート開始 → ユーザー操作で音声解除） |

### 5.2 【将来】規模拡大時の要件

複数ユーザーに開く場合に追加で必要になるもの。**v1 では実装しないが、設計を塞がない。**

| 分類 | 要件 |
|---|---|
| 認証 | OIDC + JWT 検証（`users.external_sub` を v1 から持つ） |
| スケール | DAU 1,000 / 1ユーザー 1日 5回。この規模では `claude-opus-5` で月 53万円規模になる（[05](./05-llm-design.md) §3）ため、モデル選定が事業判断になる |
| 同時実行 | LLM のブロッキング I/O によるスレッド枯渇対策（[07](./07-operations.md) §1.2）。Java 21 への移行で仮想スレッドが使える |
| 映像コスト | 動画生成は LLM の数倍〜数十倍。複数ユーザーでは**動画を有料機能にするか、Live Avatars 等の安価な方式に切り替える**判断が必要 |
| キュー | ジョブ量が増えたら DB ポーリングから外部キュー（Redis / SQS）へ移行 |

### 【v1】スコープ外

- 複数ユーザー・ソーシャル機能・課金
- 達成時の動画演出（テキストのみ）

### 恒久的にスコープ外

- ユーザー同士の相互煽り（安全設計が別物になる）

## 7. 主要な設計判断とその理由

| 判断 | 理由 | 代替案と却下理由 |
|---|---|---|
| 煽り生成に LLM を使う | 目標内容・進捗の質・履歴に**文脈依存**した煽りでないと刺さらない。テンプレは 3日で飽きる | テンプレ固定 → 単調。ただしフォールバックとしては必須 |
| プロバイダを抽象化し、**3実装を持つ** | 煽り生成は品質とコストのトレードオフが大きい。実測して比較したい。**この比較自体がポートフォリオの主題** | 特定 SDK 直結 → 乗り換えコストが高く、比較もできない |
| **煽り文は同期で返し、音声・映像は非同期にする** | テキストは2秒で出せる。ここまで非同期にすると体験が悪化するだけで得るものがない。**同期と非同期の境界を意図的に引く** | 全部同期 → 数分の白画面。全部非同期 → 即座に刺さる体験が失われる |
| **ジョブ状態を DB に永続化する** | 外部 API 呼び出しは課金済み。プロセス再起動で失うのは金銭的損失。**「途中で落ちても再開できる」ことが技術的な見せ場** | インメモリ → Railway の再デプロイのたびに消える |
| **生成物を自前のストレージに保存する** | Hedra の `download_url` は有効期限が非公開。切れると過去の履歴が全部再生できなくなる | 外部 URL をそのまま保存 → 履歴が壊れる。Character-3 を選んだ理由（履歴の再生）が半分消える |
| **VOICEVOX を自前ホストする** | 費用0。かつ「推論コンテナを自分で運用する」ことが Q5 の読者に対する情報量になる | 商用 TTS → 費用増。映像 API 内蔵 TTS → 声の選択肢が狭く、コンテナ運用の要素が消える |
| **音声を自前生成して映像 API に渡す** | 声とキャラクターを独立に選べる。映像 API を差し替えても声が変わらない | 映像 API に丸投げ → `AvatarVideoGenerator` 差し替え時に声も変わる |
| 怒りゲージを明示的な UI にする | 「怒りを力に変える」というコンセプトを、ユーザーが認知できる形に落とす必要がある | 暗黙のスコアリング → コンセプトが伝わらない |
| **達成時演出を v1 ではテキストにする** | 体験の頂点だが、動画にすると1体験あたりの生成が2本になりコスト枠が半減する。**カタルシスの保証はテキストでも満たせる** | 動画化 → v1 が完成しないリスクが上がる |
