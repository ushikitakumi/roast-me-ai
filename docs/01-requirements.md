# 01. 要件定義

> 更新日: 2026-09-08。初期版の決定一覧と完成条件は [README](./README.md)。本書は実装予定。

## 1. 目的と前提

本人1人が、ライバルへの反発心を行動の動機に使う。併せて、外部AIの連鎖・非同期処理・復旧・費用制御を示すバックエンドのポートフォリオとする。怒りが本人の行動につながったという既存の本人実験を前提とし、一般ユーザーへの効果は主張しない。

本人専用、Basic 認証 + HTTPS、日本語、個人利用。複数ユーザー・未成年向けの提供は初期版に含めない。開発者はSpring以外を学びながら実装する。旧見積もり48〜70時間は参考値で、追加した削除・費用予約等を踏まえて工程ごとに見直す。

## 2. キャラクターとコアループ

AIで事前制作したアニメ・イラスト調のライバル1体を固定利用する。成人の同年代に見える、少し生意気な表情、正面寄りの胸上、顔・口元が隠れない構図。声は中性的で落ち着きがあり余裕を感じさせるもの。話者は試聴・条件確認後に決定する。アプリ内で画像・人格は生成しない。

1. タイトルと勝利条件を入力し、目標を宣言する。
2. 進捗区分と自由記述を投稿する。通常は無料定型文、希望時だけ動画生成。
3. 本人が再生したライバルの挑発を動機に行動する。
4. 本人が達成を宣言したら、無料定型文でライバルが負けを認める。

同じキャラクターとの関係を継続する。将来は見た目・性格を含むキャラクター選択と、対応する声への変更を提供する。標準音声を持たせつつ、人格と音声設定は分離する。

## 3. 煽りの振る舞い

| 場面 | 必須の反応 |
|---|---|
| 宣言と実績に差がある | 本人の報告にある差だけを突く。未報告をサボりとしない |
| 順調 | 成果を認めて継続を挑発。合格ラインを引き上げない |
| 意図的な休み | 休む判断を責めず、再開に向けて挑発 |
| 体調不良・疲労 | それだけでは停止しない。休養を責めず「休んだらまた実力見せてよ」と返す |
| 目標達成 | 本人の宣言を受け入れ、勝利条件を織り込んで負けを認める。審査・追加課題なし |
| 取りやめ | 追い打ちなし。履歴は残す |
| 停止中 | 挑発のない短い定型文。目標管理・記録・達成は利用可能 |

強度は `MILD`（弱）/ `NORMAL`（標準・既定）/ `SAVAGE`（強）。人格・容姿・出自・病気自体・自傷を攻撃対象にしない。強度を上げても禁止対象は変えない。失敗歴・数値・努力の不足を捏造しない。

通常投稿の定型文は勝利条件・進捗区分・強度を使用し、同一目標で直前と同じ文を避ける。自由記述から未確認の事実を補わない。動画希望投稿では具体的な自由記述を区分より優先し、曖昧なら断定を避ける。

煽りは短い2文、読み上げ約10秒を目安とする。テキスト・音声・動画は同じ本文を使用する。具体的な文字数は音声実測後に調整する。

## 4. 機能要件

| ID | 初期版の必須機能 |
|---|---|
| F-A01 | Basic 認証、本人以外のアクセスを拒否 |
| F-A02 | 煽るアプリであること、強度変更・停止方法、音声クレジットの表示 |
| F-G01 | 目標作成。タイトル・勝利条件は必須、詳細・期限は任意 |
| F-G02 | 進行中・達成・取りやめの一覧、詳細、履歴 |
| F-G03 | 本人による達成。外部AIなしで必ず勝利の定型文を返す |
| F-G04 | 取りやめ。追い打ちなし。再開・編集UIは初期版に含めず、新規作成でやり直す |
| F-R01 | 5区分（できた・一部できた・できなかった・意図的な休み・体調不良）と自由記述（最大1000字） |
| F-R02 | 通常投稿は無料定型文。動画生成は目標作成・進捗投稿ごとの明示選択 |
| F-R03 | 動画希望時はLLM本文 → VOICEVOX音声 → アバター動画、R2保存、段階表示 |
| F-R04 | 全メディア手動再生。音声から動画への自動切り替えなし |
| F-R05 | アプリ全体で動画生成1件、待ち行列なし。通常投稿は継続可能 |
| F-R06 | ジョブ永続化。受付済みは復旧、受付不明は再送しない |
| F-R07 | 進捗削除と再投稿。編集不可。対応・参照先の煽りを非表示化 |
| F-C01 | 日次/月次予算の事前予約と無料定型文への縮退 |
| F-C02 | LLM・音声・動画の費用、予約、試行、レイテンシを記録。削除しても費用は残す |
| F-S01 | 即時の手動停止、強度変更、深刻な危険入力への自動停止 |

目標の勝利条件と宣言は作成後変更しない。期限経過は表示上の情報であり、自動失敗・終了・煽りのトリガーにはしない。期限後も投稿・達成できる。

## 5. 停止・無効化・削除

| 操作 | 表示・生成への効果 |
|---|---|
| 手動停止 | 再生中のメディアを即停止。未着手処理を止め、生成待ち・生成中の煽りを永続的に非表示にする。明示再開まで穏当応答 |
| 深刻な危険入力 | 同じ停止を行い、24時間経過後の本人操作まで解除不可。時間経過・再ログインだけでは再開しない |
| 強度低下 | 再生中のメディアを停止。変更前の強度で生成中の煽りを非表示。次の投稿から新強度、自動再生成なし |
| 達成・取りやめ | その目標の未着手処理を止め、生成中の煽りを以後の画面・履歴に表示しない |
| 進捗削除 | 報告と対応する煽り、および当該報告を参照した後続煽りを非表示・文脈対象外にする。後続報告は残す |

すでに外部サービスが受け付けた生成の取消成功や返金は保証しない。非表示と課金確認は別に管理する。削除された情報を間接的に引用しないよう、文脈の入力IDを記録する。停止解除や強度変更で無効化済みの煽りを復活させない。

過去に完成済みの履歴は達成・取りやめだけでは削除しない。停止中は過去の煽りの表示・再生も抑止し、解除後は無効化されていない履歴のみ利用可能。詳細は [06](./06-frontend-design.md)。

## 6. 予算・待機・障害

生成費用は月20ドル以内、日本時間の暦日・暦月で集計。インフラ別枠。日次上限額・バックエンド打ち切り時間は実測後に設定する。1日3〜5本は保証せず、1日1本等に減らして予算優先、それでも無理ならサービス再選定。

有料処理の前に見込み費用を確保する。予約不足・停止中・生成枠使用中は、有料処理や待ち行列を開始せず理由付きの無料応答にする。受付不明・結果不明の費用予約は、未課金または実費が確認できるまで保持する。

画面は投稿から3分で待機終了。バックエンドは継続し、通常の完了なら履歴に表示する。バックエンドの打ち切り時間を超えたら `RESULT_UNKNOWN` とし枠を解放、遅延完成は自動表示しない。受付不明は `SUBMISSION_UNKNOWN` として自動再送せず、テキスト・音声までを成果として残す。

## 7. 非機能と完成判定

単一ユーザー・単一アプリインスタンスを前提とする。テキストp95 4秒、音声10秒、動画3分は旧設計の目標値であり実測前の保証ではない。無料定型文は外部AIに依存せず返す。APIキーはバックエンドに限定、R2は非公開、本文をログに出さない。

Chrome/Safariを対象とし、キーボード操作、テキスト併記、色に依存しない状態表示、`prefers-reduced-motion` を尊重する。

完成条件は [READMEのAC1〜AC6](./README.md)。安全・コスト・削除・不明ジョブの検証を含めた具体的手順は [07](./07-operations.md) に定義する。単にデプロイできただけでは完成としない。
