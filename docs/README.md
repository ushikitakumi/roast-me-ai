# roast-me-ai 設計ドキュメント

「目標に向かうユーザーをアバターが煽り、その怒りを推進力に変える」Web アプリの要件定義・設計書です。

---

## このプロダクトは何か

**自分のための1人用アプリ。かつ、AI/LLM 応用ができるバックエンドエンジニアとしてのポートフォリオ。**

目標に向かう進捗をテキストで投稿すると、**イラスト調のアバターが動画で煽ってくる**。ムカついたら「ムカついた」を押して怒りゲージを溜め、その勢いで着手する。

公開 URL は出さず、Basic 認証で開発者本人だけが使う。デプロイするのは「動くものがある」ことをポートフォリオとして示すためであり、ユーザーを集めるためではない。

### 一枚看板

> **LLM → TTS → 動画生成という3段の外部 API 連鎖を、最速の成果物から順に返す段階的レスポンスとして設計し、途中で落ちても再開できるようにした。**

これが技術的な見せ場であり、設計上の主題でもある。

---

## v1 の処理パイプライン

```
進捗テキスト
  └─ [Claude / OpenAI / テンプレート]  →  煽り文     … 約2秒で表示
       └─ [VOICEVOX (自前 Docker)]     →  音声(WAV)  … 数秒で再生開始
            └─ [Hedra Character-3]      →  映像(MP4)  … 数十秒〜数分で差し替え
                 └─ [Cloudflare R2]     →  永続保存    … 履歴として再生可能
```

各段の完了は **DB のジョブ状態**として永続化する。フロントは 2〜3秒ごとにポーリングし、届いたものから表示する。ページを離れても、完成した動画は履歴に現れる。

## v1 スコープ

| 領域 | v1 に入るもの |
|---|---|
| 認証 | **Basic 認証**（単一ユーザー） |
| 目標 | 作成 / 一覧 / 詳細 / 達成 |
| 煽り | 進捗投稿 → 煽り文 → 音声 → 動画（非同期・段階表示） |
| 生成 | **Claude / OpenAI / テンプレート の3実装**、実測コスト比較 |
| 音声 | **VOICEVOX**（自前 Docker ホスト、費用0） |
| 映像 | **Hedra Character-3**（非同期）、イラスト調アバター |
| 保存 | 音声・動画を **Cloudflare R2** に永続保存し履歴で再生 |
| 反応 | 「ムカついた」+ **怒りゲージ** |
| コスト | 日次上限 + 到達時の**自動フォールバック**（テキストのみ） |
| 安全 | 入力ガード / 出力ガード / セーフモード |
| 運用 | コスト計装、`RestTestClient` による API テスト |

### v1 で削ったもの と その理由

| 削った機能 | 理由 |
|---|---|
| **Live2D アバター** | Q8 で「アバター動画」が本体になったため役割が消えた。動画生成が Live2D の上位互換になる。ライセンス確認の未決事項も同時に解消 |
| **OIDC（Google ログイン）** | 利用者が本人1人。認可コードフロー + JWT 検証に 8〜12h を使うより、Basic 認証（+1h）で浮いた時間を非同期ジョブ設計に回す方が、ポートフォリオとしての情報量が多い |
| **達成時の「負けを認める」動画** | 体験の頂点だが、1体験あたりの動画生成が 2本になりコストと工数が倍。**v1 は達成時演出をテキストのみ**にして、動画は煽り1本に絞る |
| **複数ペルソナ（3種）** | 1ペルソナにつき「イラスト1枚 + VOICEVOX 音声 + プロンプト」が必要。v1 は1体に絞る（`persona_id` は残すので追加は差分作業） |
| **Web Push / 停滞検知バッチ / 期限通知** | 1人用なので通知の価値が薄い。`@Scheduled` の枠組みはジョブ復旧で使うため設計自体は残る |
| **Redis** | 単一インスタンス・単一ユーザーではレート制限もキャッシュも DB とインメモリで足りる。運用コンポーネントを1つ減らす |
| **ストリーク / 実績 / シェア画像** | コアループの検証に不要 |
| **DAU 1,000 を前提とした規模設計** | 前提が消えた。**設計書に残る規模の記述は「将来構想」であり v1 の目標値ではない** |

上記はいずれも**設計から消したのではなく、v1 のスコープから外しただけ**である。各ドキュメントには `【将来】` として残してあり、拡張時に設計をやり直す必要はない。

## 決定一覧

要件を詰める過程で確定した判断とその根拠。

| # | 論点 | 決定 |
|---|---|---|
| Q1 | 誰のためのものか | 個人利用 + ポートフォリオ |
| Q2 | 体制と経験 | 1人開発。**Spring 以外はすべて未経験**（React / TS / Next.js / プロンプト / インフラ） |
| Q3 | 「怒りが行動を生む」は本当か | 本人が数日間かけて実測し **Yes**。前提クリア |
| Q4 | 静止画差分の扱い | 動画採用により「待機状態の表示」に役割変更 |
| Q5 | ポートフォリオの読者 | **AI/LLM 応用ができるバックエンドエンジニア** |
| Q6 | 公開範囲 | デプロイするが**本人のみログイン可**。公開 URL は出さない |
| Q7 | 工数予算 | 引き上げて Spring Boot + Next.js/React 構成を維持 |
| Q8 | アバター表現 | **映像を採用**。映像は装飾ではなくプロダクトの本体 |
| Q9 | 既存設計書の扱い | 将来構想として残し、本 README に v1 スコープと削った理由を書く |
| Q10 | アバターの画風 | **イラスト/アニメ調で開始**、将来実写 → `AvatarVideoGenerator` ポートで抽象化 |
| Q11 | 音声生成 | **VOICEVOX を自前ホスト**し、映像 API に音声を渡す（費用0） |
| Q12 | コスト上限 | **月 $10〜20 / 1日3〜5本**。上限到達で**自動でテキストのみに縮退** |
| Q13 | 映像 API | **Hedra Character-3（非同期）**。Live Avatars は不採用 |
| Q14 | 認証方式 | **Basic 認証** |
| Q15 | 生成プロバイダ | **Claude + OpenAI + テンプレート の3実装** |
| Q16 | 待ち時間の体験 | **段階表示を試み、一定時間で完全非同期に落とす** |
| Q17 | デプロイ先 | **Vercel（Next.js）+ Railway（Spring + PostgreSQL + VOICEVOX）** |
| Q18 | 動画の保存 | **Cloudflare R2 に自前保存**（Hedra の `download_url` は期限が非公開のため） |
| Q19 | ジョブの耐久性 | **DB ジョブテーブル + `@Async` + `@Scheduled` 復旧** |
| Q20 | 完了通知 | **ポーリング**（2〜3秒間隔） |
| Q21 | コアループ | ムカついたボタン + 怒りゲージ。**達成時演出はテキストのみ** |
| Q22 | 実装順序 | **縦に薄く貫く**（walking skeleton 優先） |

### 選ばなかった選択肢（意図的な不採用）

| 論点 | 選ばなかったもの | 理由 |
|---|---|---|
| 映像 API | HeyGen | **写実的な人物のみ**対応。イラスト調アバターに使えない |
| 映像 API | D-ID | アニメ・イラスト・動物で**顔検出に失敗しうる**。Hedra Character-3 は非人間の顔を明示的にサポート |
| 映像 API | Hedra **Live Avatars**（$0.05/分・低遅延） | 安くて速いが、作業が React + WebRTC に寄りバックエンドがトークン発行だけになる。VOICEVOX 採用とも噛み合わず、履歴として再生できない。**レイテンシ問題こそが見せ場**なので非同期の Character-3 を採る |
| 通知 | SSE / WebSocket | 更新が3段階・数十秒スケールのため、常時接続の維持コストに見合わない。Vercel の関数タイムアウトと Railway 越しの長時間接続という追加リスクも避ける |
| インフラ | Cloud Run（ゼロスケール） | **技術的にはこちらが最適**。VOICEVOX は使用時のみ起動すればよくコールドスタートを許容できる設計になっている。今回はインフラ未経験による工数リスクで Railway を選択。**コスト最適化の次の一手として明確** |
| API バージョニング | Spring Framework 7 の `spring.mvc.apiversion.*` | BFF が唯一のクライアントで v2 が存在しない。パス方式 `/api/v1` で足りる |
| レジリエンス | Resilience4j | Spring Framework 7 標準の `@Retryable` / `@ConcurrencyLimit` で足りる。**ただしサーキットブレーカは標準に含まれない**ため、そこだけ自前実装 |

## 実装順序

| | 内容 | 目安 |
|---|---|---|
| **P0** | **前提検証**（下記「着手前に潰す前提」を1時間で実施） | 1h |
| **P1** | 縦串：ローカル、認証なし、UI は `<button>` と `<video>` だけで「テキスト → Claude → VOICEVOX → Hedra → 再生」を1本通す | 15〜20h |
| **P2** | ジョブ永続化 + 段階表示 + R2 保存 | 8〜12h |
| **P3** | Basic 認証 + Vercel / Railway デプロイ | 8〜12h |
| **P4** | UI 整備 + 怒りゲージ | 8〜12h |
| **P5** | 3プロバイダ比較 + コスト計測グラフ | 5〜8h |
| **P6** | README / 設計書の v1 スコープ整理 | 3〜5h |

**合計 48〜70時間。**

- **P3 まで到達すれば「デプロイまで完了」という当初目標は達成される。** P4 以降は積み増しなので、時間が尽きても手元に動くものが残る
- P4（個人利用としての価値）と P5（ポートフォリオとしての価値）は独立しており、順序は状況に応じて入れ替えてよい
- **P1 を最優先にする理由は工数管理ではなく、未知の潰し方**にある。3段の外部 API 連鎖は繋いでみるまで何が壊れるか分からない

## 着手前に潰す前提（P0）

Hedra の無料枠でイラスト画像1枚 + VOICEVOX の WAV を投げ、**10秒の動画を1本作って記録する。** 下表の 1〜4 が同時に潰れる。

| # | 未検証事項 | 外れた場合の影響 |
|---|---|---|
| 1 | **イラスト調画像で Character-3 が顔を認識するか** | **Q10 が崩壊。** 実写での開始に変更 |
| 2 | **VOICEVOX の WAV を Hedra が受けるか**<br/>（Hedra 公式サンプルは `.wav` / `.mp3` を使うため形式は合う見込み。ただしサンプリングレート・チャンネル数の許容範囲は非公開） | **Q11 が崩壊。** Hedra 内蔵 TTS に切替（コスト増） |
| 3 | **Character-3 の実生成時間**（非公開） | 段階表示のタイムアウト値とフォールバック設計が変わる |
| 4 | **Hedra のクレジット→ドル単価** | 1日3〜5本という Q12 の見積もりが変わる |
| 5 | **VOICEVOX のキャラクター個別規約が「煽り」を許すか**<br/>（P0 とは別に、規約を読む作業として必要） | キャラクター変更。最悪 Q11 が崩壊 |
| 6 | Hedra `download_url` の有効期限（非公開） | **Q18 の R2 保存で対策済み** |

> **VOICEVOX のクレジット表記は必須**（例: `VOICEVOX:ずんだもん`）。商用利用でクレジットを欠くと使用料が発生する。本プロジェクトは非商用だが、表記は入れる。

## 技術スタック（要約）

- **バックエンド**: Java 17 / **Spring Boot 4.1（Spring Framework 7）** / PostgreSQL 16 / Flyway
- **フロントエンド**: TypeScript / Next.js 15 / React 19
- **AI**: Claude（既定 `claude-opus-5`）+ OpenAI + テンプレート / VOICEVOX / Hedra Character-3
- **インフラ**: Vercel + Railway + Cloudflare R2
