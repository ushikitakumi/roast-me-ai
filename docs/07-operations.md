## 1. 事前検証

画像1枚と音声から約10秒の動画を作り、次の結果を記録する。未検証値を実装の既定値にしない。従来の「1時間」は目安であり検証終了の保証ではない。

| 項目 | 現在 | 記録する結果 |
|---|---|---|
| 画像 | 未制作・未検証 | 成人のライバル、正面寄り胸上、顔・口元の認識と出力品質 |
| 声 | 方針のみ確定 | 中性的・落ち着き・余裕のある候補の試聴、話者ID、条件、クレジット |
| WAV互換性 | 未検証 | サンプリングレート・チャンネル・実測尺・変換の要否 |
| 動画サービス | Hedra Character-3候補 | 現行API、利用条件、画像/音声入力、受付確認手段、取消可否 |
| 費用 | 月20ドルのみ確定 | 約10秒の実費、最低購入額等の固定費、LLM費用、見積もり上限 |
| 所要時間 | 未検証 | 本文/音声/動画の実測、失敗時挙動 |
| 日次予算 | 未確定 | 月20ドルとの整合、日次上限額、本数を減らす必要 |
| 結果待ち打ち切り | 未確定 | 画面の3分とは別のバックエンド期限 |
| 技術互換性 | 未検証 | Java/Boot、Next.js/React、SDK、DB、テストツールのビルド可能な組み合わせ |
| 支援先 | 未確定 | 公的なURL・表示文言、確認日 |

無料枠の存在や外部サービスの過去価格を前提にしない。検証の実費も記録し、月予算の残額に含める。動画の本数を減らしても予算内に収まらなければサービスを再選定する。イラスト認識失敗なら構図やサービスを見直し、合意なしに実写へ変更しない。

### S0: 前提検証（P0）

- **作業**: §1の技術互換性・モデル/API・話者条件を確認。固定ライバル画像と音声を準備し、約10秒の動画を少数回検証する。外部呼び出しは自動再送せず、検証支出を記録する。
- **成果物**: §1に日付、公式情報の参照先、画像/音声の選定結果、実測費用・所要時間・形式を追記。日次額とバックエンド打ち切り時間を確定し、検証スクリプトを保存する。秘密情報は含めない。
- **完了条件**: 月20ドルの範囲で成立する使い方を説明でき、後続で使う素材・話者・API契約が確認済み。成立しなければ予算優先で本数/サービスを見直す。未確認の項目は保留として残す。

この外部適合性の少数回検証と、アプリ内の有料機能有効化は別。検証済み支出はS5の費用台帳に取り込み、月予算を二重に使わない。

### S1: 開発環境と起動（P1の土台）

- **作業**: `backend/` にSpring Boot、`frontend/` にNext.js、ローカルPostgreSQLのCompose設定を作成。依存を固定し、Flyway・ヘルスチェック・テスト起動・環境変数例を用意する。有料通信は無効を既定にする。
- **成果物**: 再現可能なビルド/起動コマンド、秘密を含まない設定例、基本CI。実装時に採用したコマンドを本書へ記録する。
- **完了条件**: 空のDBから起動し、バックエンドとフロントのビルドが通る。外部APIキーなしで開発可能。ローカル構成を無認証のまま外部公開しない。

### S2: 無料の目標・進捗API（P1）

- **作業**: users、personas/voices、settings、goals、progress、roasts、入力参照、冪等キーを段階的にmigrationへ追加。目標作成/一覧/詳細、5区分の投稿、定型文、達成、取りやめ、履歴を実装する。
- **成果物**: [03](./03-api-design.md)の無料応答に対応するAPI、OpenAPI、テンプレートとドメイン/DBテスト。具体話者が未確定ならローカル専用の仮マスタを使い、実音声として扱わない。
- **完了条件**: 宣言→報告→勝利がAPIで通り、外部通信0件。勝利条件必須、期限超過でも投稿可能、達成/取りやめ後の投稿拒否、同文連続回避、同一キー再送で重複作成なしを確認する（AC6の基礎）。

### S3: 無料コアループの画面（P1）

- **作業**: 一覧、作成、詳細、5区分+本文フォーム、履歴、達成、取りやめを作る。OpenAPIから通信型を生成し、BFF経由で接続する。
- **成果物**: ブラウザで一通り使える無料アプリ。動画希望は既定OFF、未実装の有料生成は選択不可とする。
- **完了条件**: ブラウザから勝利まで完了でき、再読込後も保存内容が残る。送信中の重複操作とネットワーク再試行で同じ冪等キーを維持する。編集・比較画面等を追加しない。

### S4: 本人認証と表示を止める操作（P3/P4の先行実装）

- **作業**: 二系統Basic認証、所有者確認、BFF許可リスト/CSRF対策、入力ガード、強度と手動/自動停止、進捗削除を実装。入力参照と設定世代に基づく表示資格を共通化する。
- **成果物**: 停止/再開/強度設定と削除UI、API認可・安全状態・削除参照のテスト。将来のジョブにも同じ無効化ルールを適用できるサービス境界。
- **完了条件**: 未認証/他人のIDを拒否、削除した報告と参照先煽りが取得不可。停止中も記録・達成は可能。体調不良のみでは停止せず、自動停止は24時間+明示解除を守る（AC1/AC4/AC6の基礎）。

### S5: 有料処理前の予算と1件枠（P2/P3の先行実装）

- **作業**: 予算予約、費用台帳、アプリ全体の生成枠をmigrationとサービスに追加。確保・追加予約・精算・予約保持・解放を実装する。S0支出の登録も可能にする。
- **成果物**: `/me` の予算/利用可否、無料縮退判断、DB並行実行テスト。実測値が未定でもテスト設定で境界検証を行う。
- **完了条件**: 複数タブ相当の同時要求でも1件しか確保しない。日次/月次不足は有料処理0件。日/月境界でも不明予約を保持し、実費と予約の二重加算なし（AC5）。

### S6: スタブで永続パイプラインを通す（P2）

- **作業**: 外部ポートとスタブ、同期本文から非同期音声/動画への遷移、ジョブmigration、投入意図の先行保存、外部ID保存、コミット後の起動を実装。生成前に入力参照を登録する。
- **成果物**: 動画希望時にのみ202と段階状態を返すAPI、ローカルテスト用メディア、非同期契約テスト。R2本番接続は不要。
- **完了条件**: 通常投稿と任意動画の分岐が通る。停止・予算・枠の判定を迂回せず、各段の状態と成果物がDBに残る。外部の有料通信はまだ有効にしない（AC2の基礎）。

### S7: 落として復旧と競合を検証する（P3）

- **作業**: リース・世代照合・復旧スケジューラ、受付不明/結果不明、遅延結果の隔離、非表示中の精算を実装。各段で再起動や削除・停止等を挟むテストを作る。
- **成果物**: Testcontainers/WireMockで再現可能な障害・競合テストと、不明ジョブの確認手順。
- **完了条件**: 外部IDありはstatusから復旧、投入とID保存の隙間は再submitしない。不明終了で枠だけ解放し予約保持。古いワーカーや遅延応答で本文・動画を復活させない（AC3/AC4/AC5）。

### S8: 手動メディア再生と待機（P2/P4）

- **作業**: 都度認可するメディア配信（Rangeを含む）、段階表示、3分の画面待機、履歴再生、音声クレジット、即時pauseとキャッシュ無効化を実装する。
- **成果物**: スタブの動画で確認できる画面、Vitest等による状態/再生/停止の検証。
- **完了条件**: 音声も動画も手動再生。音声再生中の動画完成で切り替わらない。画面3分終了は生成を取り消さず、停止・削除後の新規配信を拒否する。別タブや遅い取得結果でも表示を復活させない（AC2/AC4）。

### S9: 実サービスで縦に通す（P2/P3の結合確認）

- **作業**: S0で確認したLLM1実装、VOICEVOX、Hedra、R2のアダプタを接続。プロンプト/出力検査、実測尺での予約再評価、実費計装を組み込む。仮の素材・設定を確定値へ置換する。
- **成果物**: 予算内で実行した目標作成/投稿の動画、段階別計測、選定した声のクレジット、実APIの確認記録。
- **完了条件**: S0の費用も含む残予算内で、本人が選んだ投稿のみ同じ本文の音声・動画が生成される。無料投稿・達成に外部AI不要、失敗は設計どおり縮退する。短い2文・約10秒と事実整合を確認する。

### S10: デプロイと初期版の完成確認（P4）

- **作業**: Vercel/Railway/R2の本番設定、秘密情報、内部ネットワーク、配信制限を確認。全ACと追加必須ケースをデプロイ環境で確認し、運用手順・起動方法・実測値を更新する。
- **成果物**: 本人専用の動作環境、ACごとの証跡、採用依存/設定値、検証済みコマンド、既知の制約。
- **完了条件**: §3のAC1〜AC6と追加必須ケースを満たす。未実装の安全・復旧・費用制御を残さない。ここを初期版完成とし、怒りゲージ等は別の後続作業にする。

### 2.2 各ステップの終わり方

実装した内容、変更ファイル、実行した検証と結果、未完了事項、次に進めるステップを短く記録する。表の「完了証跡」はテスト/記録への参照とし、コミットした場合はそのIDも添える。テストが未実行なら未実行と書く。コミット・プッシュの実行は、その作業時点のユーザー指示に従う。

範囲は現在の設計に限定する。実測で前提が外れた場合は、影響する仕様と理由を記録し、依存しない作業を続ける。金額・規約・APIの未確認事項を推測で埋めて有料機能を有効化しない。

## 3. 受入テスト

| ID | 手順・期待結果 |
|---|---|
| AC1 | 未認証は拒否、本人は勝利条件必須で作成できる。他人のIDは404。作成後編集APIなし |
| AC2 | 通常投稿で有料外部通信0件・定型文。動画希望時だけ段階表示。音声/動画が勝手に再生されず、音声再生中の動画完成でも切り替わらない |
| AC3 | 外部ID保存後にプロセスを停止・再起動し、statusから復旧、submit回数1。投入成功後ID保存前の停止・応答喪失ではSUBMISSION_UNKNOWN、submit再送0回 |
| AC4 | 同期LLM中・音声生成中・動画投入中・完成公開直前に停止/強度低下/達成/取りやめ/削除を挟み、対象本文・URLが通常API・履歴・冪等再送から返らない |
| AC5 | 日次/月次それぞれ残額不足、同時投稿、日/月境界、不明予約持越しを検証。有料処理を開始せず無料応答。精算で実費と予約を二重加算しない |
| AC6 | 予算0・LLM障害・停止中でも達成操作で無料勝利文。実績の捏造、追加課題、達成後の未完成煽りの表示なし |

追加の必須ケース:

- DONEでも本文が部分達成なら、有料LLMは具体的な記述に基づく。未報告を未実施と断定しない。
- REST/UNWELL/疲労は煽りを自動停止せず、休養を責めない。深刻な危険入力は停止し、24時間前の解除は拒否。経過だけでは解除せず本人操作を要求する。
- 手動停止は即時再生停止。通常記録・達成は使え、再ログインで勝手に解除されない。
- 目標期限後もACTIVEで投稿可能。取りやめは追い打ちなし、編集・再開なし。
- 報告Aを参照する後続煽りBを生成後、A削除で両方の煽りが非表示。Bの元になった後続報告は残り、有料費用は減らない。生成中にAを削除した場合も同じ。
- アプリ全体の生成枠は1件、待ち行列なし。通常投稿は可能。画面3分終了で枠を解放せず、バックエンド打ち切り時はRESULT_UNKNOWNとして解放する。
- 不明終了後の遅延完成は通常履歴に出ず、費用確認だけを更新する。予約は未課金/実費確認まで保持。
- 定型文は勝利条件・区分・強度に合い、同一目標で同文が連続しない。

## 4. テストとCI

JUnitでドメイン/テンプレート、ArchUnitで境界、TestcontainersでDB・予算ロック・参照削除、WireMockで外部の拒否/429/5xx/タイムアウト/結果不明を検証。Vitestで表示状態・再生・停止・ポーリング・再送キーを検証。採用バージョンに合うAPIテストクライアントでOpenAPI契約を確認する。

実APIは手動実行・予算内。CIはスタブのみ。危険入力・インジェクション・休養の誤停止・事実整合の代表例を固定し、期待する停止/非停止・出力制約を明記する。安全・予算・復旧の必須ケース未達はリリースを止める。単に「安全性テスト全件パス」と書くだけで未知入力の完全検知を保証しない。

CI: backend build → 単体/境界/DB/契約/復旧、frontend typecheck/lint/test/build、OpenAPI差分、依存脆弱性確認。コード変更がない今回のドキュメント更新では、リンク・状態名・旧仕様の混入を検査する。

## 5. 環境・配信・セキュリティ

local/CIは定型文・スタブを既定にし、有料機能を明示的に有効化する。本番は本人専用。RailwayにSpring/PostgreSQL/VOICEVOX、VercelにNext.js、R2は非公開。VOICEVOXは内部ネットワークだけで公開する。認証・コストガードなしでインターネットにデプロイしない。

必要設定: 外部APIキー、R2資格情報、ブラウザ/BFF間とBFF/Spring間の別Basic資格情報、DAILY_COST_LIMIT_USD（実測後必須）、MONTHLY_COST_LIMIT_USD=20、VIDEO_RESULT_TIMEOUT_SECONDS（実測後必須）、採用モデル/音声ID、VIDEO_ENABLED（運用上の有効化）。不明値を仮の本番既定値として扱わない。

BFFは許可したAPIに限定、Origin等でCSRF対策、Springも所有者認可。外部ダウンロードは許可ホスト・リダイレクト・サイズ上限・タイムアウトを検証しSSRFを防ぐ。キー・進捗本文・煽り本文・プロンプトをログに出さない。

メディアは都度認可するBFF/Spring経由。Range配信とVercel/Railwayの実行時間・サイズ・転送費を小動画で確認する。インフラ費用は生成費月20ドルとは別に計測し、旧版の月額見積もりを保証としない。

## 6. 監視・不明ジョブの運用

記録するもの: operation/roast/job ID、provider/model、段階別レイテンシ、確定実費、未精算予約、生成枠、SUPPRESSED理由、SUBMISSION_UNKNOWN/RESULT_UNKNOWN件数、安全停止理由。本文なしで追跡できるようにする。

不明ジョブの確認手順:

1. 外部管理画面/利用明細/取得可能なIDを読み取り、受付と課金を確認する。確認のためにsubmitしない。
2. 判明した実費で精算、未課金が確認できた分だけ予約解放。証拠がなければ保持する。
3. 遅延完成はlate_resultとして記録する。通常履歴へ自動公開しない。初期版に公開し直すUIは設けない。
4. 請求と見積もりのずれがあれば有料生成を停止し、料金・尺・予約上限を修正する。

上記の運用確認はログ・DB/管理手順で行い、初期版の比較画面とは別。表示抑止だけで外部処理の中止・返金を主張しない。物理削除の運用でも監査用IDと費用台帳は保持する。

## 7. 残る実測事項

プロダクト上の主要な判断はヒアリングで確定。未確定なのは§1の外部適合性・実費・所要時間・具体話者・依存互換性。結果は本書へ日付・条件・証跡とともに追記し、日次額/バックエンド期限を関連設計へ反映する。比較画面や声選択を先に実装して初期版の範囲を広げない。
