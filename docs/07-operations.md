# 07. 非機能・運用・実装ロードマップ

> 更新日: 2026-09-08。完成条件は [READMEのAC1〜AC6](./README.md)。デプロイだけで初期版完成とはしない。

## 1. 事前検証

画像1枚と音声から約10秒の動画を作り、次の結果を記録する。未検証値を実装の既定値にしない。従来の「1時間」は目安であり検証終了の保証ではない。

| 項目 | 現在 | 記録する結果 |
|---|---|---|
| 画像 | 未制作・未検証 | 成人のライバル、正面寄り胸上、顔・口元の認識と出力品質 |
| 声 | 方針のみ確定 | 中性的・落ち着き・余裕のある候補の試聴、話者ID、条件、クレジット |
| WAV互換性 | 未検証 | サンプリングレート・チャンネル・実測尺・変換の要否 |
| 動画サービス | Hedra Character-3候補 | 現行API、利用条件、画像/音声入力、受付確認手段、取消可否 |
| 費用 | 月20ドルのみ確定 | 約10秒の実費、最低購入額等の固定費、LLM費用、見積もり上限 |
| 所要時間 | 未検証 | 本文/音声/動画の実測、失敗時挙動 |
| 日次予算 | 未確定 | 月20ドルとの整合、日次上限額、本数を減らす必要 |
| 結果待ち打ち切り | 未確定 | 画面の3分とは別のバックエンド期限 |
| 技術互換性 | 未検証 | Java/Boot、Next.js/React、SDK、DB、テストツールのビルド可能な組み合わせ |
| 支援先 | 未確定 | 公的なURL・表示文言、確認日 |

無料枠の存在や外部サービスの過去価格を前提にしない。検証の実費も記録し、月予算の残額に含める。動画の本数を減らしても予算内に収まらなければサービスを再選定する。イラスト認識失敗なら構図やサービスを見直し、合意なしに実写へ変更しない。

## 3. 受入テスト

| ID | 手順・期待結果 |
|---|---|
| AC1 | 未認証は拒否、本人は勝利条件必須で作成できる。他人のIDは404。作成後編集APIなし |
| AC2 | 通常投稿で有料外部通信0件・定型文。動画希望時だけ段階表示。音声/動画が勝手に再生されず、音声再生中の動画完成でも切り替わらない |
| AC3 | 外部ID保存後にプロセスを停止・再起動し、statusから復旧、submit回数1。投入成功後ID保存前の停止・応答喪失ではSUBMISSION_UNKNOWN、submit再送0回 |
| AC4 | 同期LLM中・音声生成中・動画投入中・完成公開直前に停止/強度低下/達成/取りやめ/削除を挟み、対象本文・URLが通常API・履歴・冪等再送から返らない |
| AC5 | 日次/月次それぞれ残額不足、同時投稿、日/月境界、不明予約持越しを検証。有料処理を開始せず無料応答。精算で実費と予約を二重加算しない |
| AC6 | 予算0・LLM障害・停止中でも達成操作で無料勝利文。実績の捏造、追加課題、達成後の未完成煽りの表示なし |

追加の必須ケース:

- DONEでも本文が部分達成なら、有料LLMは具体的な記述に基づく。未報告を未実施と断定しない。
- REST/UNWELL/疲労は煽りを自動停止せず、休養を責めない。深刻な危険入力は停止し、24時間前の解除は拒否。経過だけでは解除せず本人操作を要求する。
- 手動停止は即時再生停止。通常記録・達成は使え、再ログインで勝手に解除されない。
- 目標期限後もACTIVEで投稿可能。取りやめは追い打ちなし、編集・再開なし。
- 報告Aを参照する後続煽りBを生成後、A削除で両方の煽りが非表示。Bの元になった後続報告は残り、有料費用は減らない。生成中にAを削除した場合も同じ。
- アプリ全体の生成枠は1件、待ち行列なし。通常投稿は可能。画面3分終了で枠を解放せず、バックエンド打ち切り時はRESULT_UNKNOWNとして解放する。
- 不明終了後の遅延完成は通常履歴に出ず、費用確認だけを更新する。予約は未課金/実費確認まで保持。
- 定型文は勝利条件・区分・強度に合い、同一目標で同文が連続しない。

## 4. テストとCI

JUnitでドメイン/テンプレート、ArchUnitで境界、TestcontainersでDB・予算ロック・参照削除、WireMockで外部の拒否/429/5xx/タイムアウト/結果不明を検証。Vitestで表示状態・再生・停止・ポーリング・再送キーを検証。採用バージョンに合うAPIテストクライアントでOpenAPI契約を確認する。

実APIは手動実行・予算内。CIはスタブのみ。危険入力・インジェクション・休養の誤停止・事実整合の代表例を固定し、期待する停止/非停止・出力制約を明記する。安全・予算・復旧の必須ケース未達はリリースを止める。単に「安全性テスト全件パス」と書くだけで未知入力の完全検知を保証しない。

CI: backend build → 単体/境界/DB/契約/復旧、frontend typecheck/lint/test/build、OpenAPI差分、依存脆弱性確認。コード変更がない今回のドキュメント更新では、リンク・状態名・旧仕様の混入を検査する。

## 5. 環境・配信・セキュリティ

local/CIは定型文・スタブを既定にし、有料機能を明示的に有効化する。本番は本人専用。RailwayにSpring/PostgreSQL/VOICEVOX、VercelにNext.js、R2は非公開。VOICEVOXは内部ネットワークだけで公開する。認証・コストガードなしでインターネットにデプロイしない。

必要設定: 外部APIキー、R2資格情報、ブラウザ/BFF間とBFF/Spring間の別Basic資格情報、DAILY_COST_LIMIT_USD（実測後必須）、MONTHLY_COST_LIMIT_USD=20、VIDEO_RESULT_TIMEOUT_SECONDS（実測後必須）、採用モデル/音声ID、VIDEO_ENABLED（運用上の有効化）。不明値を仮の本番既定値として扱わない。

BFFは許可したAPIに限定、Origin等でCSRF対策、Springも所有者認可。外部ダウンロードは許可ホスト・リダイレクト・サイズ上限・タイムアウトを検証しSSRFを防ぐ。キー・進捗本文・煽り本文・プロンプトをログに出さない。

メディアは都度認可するBFF/Spring経由。Range配信とVercel/Railwayの実行時間・サイズ・転送費を小動画で確認する。インフラ費用は生成費月20ドルとは別に計測し、旧版の月額見積もりを保証としない。

## 6. 監視・不明ジョブの運用

記録するもの: operation/roast/job ID、provider/model、段階別レイテンシ、確定実費、未精算予約、生成枠、SUPPRESSED理由、SUBMISSION_UNKNOWN/RESULT_UNKNOWN件数、安全停止理由。本文なしで追跡できるようにする。

不明ジョブの確認手順:

1. 外部管理画面/利用明細/取得可能なIDを読み取り、受付と課金を確認する。確認のためにsubmitしない。
2. 判明した実費で精算、未課金が確認できた分だけ予約解放。証拠がなければ保持する。
3. 遅延完成はlate_resultとして記録する。通常履歴へ自動公開しない。初期版に公開し直すUIは設けない。
4. 請求と見積もりのずれがあれば有料生成を停止し、料金・尺・予約上限を修正する。

上記の運用確認はログ・DB/管理手順で行い、初期版の比較画面とは別。表示抑止だけで外部処理の中止・返金を主張しない。物理削除の運用でも監査用IDと費用台帳は保持する。

## 7. 残る実測事項

プロダクト上の主要な判断はヒアリングで確定。未確定なのは§1の外部適合性・実費・所要時間・具体話者・依存互換性。結果は本書へ日付・条件・証跡とともに追記し、日次額/バックエンド期限を関連設計へ反映する。比較画面や声選択を先に実装して初期版の範囲を広げない。
