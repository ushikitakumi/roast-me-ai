# 02. アーキテクチャ設計

> 更新日: 2026-09-19。3D試作を先行する。現行バックエンドを置き換える実装指示ではない。

## 1. 試作の構成

```text
既存Next.jsアプリの認証
  └─ アバター確認専用ページ
       ├─ 利用条件確認済みの固定3Dモデル
       ├─ 用意済みの日本語音声と台詞
       ├─ 手動再生・停止・再再生
       └─ 音声に合わせた口の開閉、まばたき、小さな顔の動き
```

Three.js・VRM/three-vrm・Web Audio APIを候補とする。具体バージョン・モデル適合性は実装時に確認し固定する。3D方式の採用合意と、VRM形式・依存バージョンの正式採用は別。試作ではSpringの生成API、LLM、TTS、Hedra、R2を呼び出さない。

## 2. 境界

描画・音声再生・音声から口の開きを求める処理・モデル固有設定を分ける。特定モデルのファイル名や表情名を画面全体へ埋め込まない。将来の自作モデル差し替えに必要な形式、口・まばたき等の対応設定、素材のクレジットを記録する。任意の3Dファイルが無調整で使えるとは保証しない。

生成と再生は別の責務。既存のAvatarVideoGeneratorは動画ファイルをsubmit/status/downloadする旧ポートであり、ブラウザ内の描画をその代替実装として偽装しない。

## 3. 現在の実装を維持する範囲

Spring Boot・Next.js・PostgreSQL、無料コアループ、Basic認証、所有者確認、BFFの許可リスト/Origin確認、停止・削除、予算台帳、旧スタブジョブを試作中は維持する。実装実績は [07](./07-operations.md)。

旧ジョブのリース・外部受付・予算テストは既存実装の証跡であり、ブラウザ描画の復旧を検証したものではない。旧構成と処理詳細は [旧アーキテクチャ](./legacy-video/02-architecture.md) を参照。

## 4. 試作合格後に設計する本体

本文と生成音声を保存し、ブラウザ上の固定アバターが同じ音声で喋り、履歴から再生する構成を目指す。音声の生成と保存、モデル資産の配信、発話の状態管理を設計する。LLM/TTSやR2等のストレージは未接続で、今回の合意では採用を確定していない。

認証・入力参照・停止/削除の表示資格・予算予約と精算は引き継ぐ。停止済みの本文・音声を遅延応答で復活させず、表示抑止と費用精算を分離する。新方式の生成完了と再生完了を混同しない。

試作合格後、API・DB・生成枠・期限・音声再試行・移行データの扱いを定めてから本体を変更する。動画生成方式との二方式運用は目指さないが、既存状態・費用記録を無条件に削除しない。
