# 06. フロントエンド設計

> 更新日: 2026-09-19。専用ページで3D試作を評価し、本人の採用判断後にコアループへ統合する。

## 1. 既存画面と試作ページ

Next.js App Router、React、TypeScript、既存の認証/BFFを維持する。旧設計の「WebGLを導入しない」は撤回し、3D描画を試作する。

| 画面 | 試作中の扱い |
|---|---|
| `/`、`/goals/new`、`/goals/[goalId]`、`/settings` | 無料コアループ・旧動画スタブを維持 |
| アバター確認専用ページ | 新規追加。具体パスは実装時に決める。既存認証の内側に置く |
| `/api/proxy/...` | 現行契約を維持。試作から生成APIを呼ばない |

## 2. 試作の体験

固定の既製3Dモデルを胸上で表示し、こちらを向いた少し生意気な表情を目指す。約10秒の日本語音声と台詞を用意し、モデル・音声のクレジットを示す。

再生・停止・再再生を手動操作する。音声に合わせた簡易口パク、まばたき、小さな顔の動きを付ける。無音・停止時は口を閉じ、停止時に音声と口パクを止める。再再生で音声を重ねない。本人が外見と喋り方を評価できることを優先する。

試作と分かる表示にし、素材の読込失敗を説明する。ページを離れた後に再生や描画処理を残さない。キーボード操作、台詞併記、reduced-motionへの配慮を行う。具体的なブラウザと端末を記録してPCで検証する。スマートフォンは今回の合格条件ではない。

## 3. 採用後の本体統合

音声の再生と同時にアバターを動かし、履歴から同じ音声を再生できるようにする。旧「動画で煽ってもらう」の操作名、生成状態の表示、音声のみの再生との関係は統合設計で確定する。試作中に既存フォームの契約を変更しない。

既存の3分ポーリング・VIDEO_*段階表示・音声から動画への切り替えは旧スタブ用で、新3D再生の要件ではない。新しい音声生成待ちとブラウザ内再生の状態を分けて設計する。

## 4. 本体で維持する停止・履歴の契約

停止・強度低下・達成・取りやめ・削除に応じて再生を止め、対象の本文とメディアを隠す。停止設定の保存に失敗しても勝手に再生を再開しない。無効化済みの煽りは再開後も復活させない。

削除済み報告と参照先の煽りを履歴・キャッシュから除去する。後続報告と費用は残す。同一ブラウザの別タブへの無効化通知、復帰時の再確認、配信時の認可を引き継ぐ。別端末での即時反映を保証しない。

本人専用の本体統合では、音声だけでなく3D側の口パクも停止対象になる。これらは試作の再生ボタンテストだけで完了とはしない。具体的な統合試験を採用後に追加する。

## 5. 合格と除外範囲

[PA1〜PA5](./01-requirements.md)を確認し、本人が採用可否を判断する。LLM/TTS接続、履歴連携、全身ジェスチャー、発音別口形、モデル/声選択UI、動画書き出しは今回の試作対象外。
