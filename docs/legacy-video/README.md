# roast-me-ai 設計ドキュメント

更新日: 2026-09-10。設計ヒアリングで確定した初期版の仕様を反映。ローカルの無料・スタブ実装を進めている。実装状況と検証結果は [07の進捗表・§8](./07-operations.md) を参照。各設計書の仕様全体が実装済み・外部サービス検証済みであることは意味しない。

## 1. プロダクトと初期版の完成ライン

本人専用の習慣化アプリ兼、AI/LLM を応用するバックエンドエンジニアのポートフォリオ。固定のライバルに目標を宣言し、煽られて行動し、本人が達成を宣言したらライバルが負けを認める。

**通常投稿は無料の定型テキスト。本人が「動画で煽ってもらう」を選んだ目標作成・進捗投稿だけ、有料の生成パイプラインを実行する。** 生成費用は月20ドル以内を優先する。

初期版の完成は、本人専用のデプロイ環境で、目標作成 → 進捗報告 → 任意の動画による煽り → 達成して勝つ、を一通り使えること。認証・コスト制御・安全機構・ジョブ復旧・履歴・取りやめ・進捗削除を含む。怒りゲージとプロバイダ比較画面は後続に回す。

## 2. 確定した判断

| 論点 | 初期版の決定 |
|---|---|
| 利用者・公開 | 本人1人、Basic 認証 + HTTPS。公開URLは配布しない |
| キャラクター | AIで事前制作した1体。アプリ内の画像・人格生成はしない |
| 人格 | 同格のライバル。宣言と報告された行動の差を突く |
| 外見 | 成人の同年代に見える、少し生意気な表情。正面寄りの胸上、顔・口元が隠れない構図。性別・服装の詳細は制作時に決める |
| 声 | 中性的、落ち着きと余裕のある声。具体的な話者は試聴・利用条件確認後に確定 |
| 将来の選択 | 見た目・性格の異なるキャラクターを選択可能にする。各キャラクターに標準の声を持たせ、対応する声から変更可能にする |
| 煽りの根拠 | 宣言と本人の報告だけ。未報告を未実施としない。失敗歴・数字を捏造しない |
| 順調な日 | 成果を認め、次の継続を挑発。合格ラインを勝手に引き上げない |
| 休み・体調不良 | 休養自体は責めず、再開に向けて挑発。疲労・体調不良だけでは自動停止しない |
| 強度 | 弱・標準・強、初期値は標準。どの強度も行動だけが対象 |
| 停止 | 手動停止は本人が再開するまで継続。深刻な危険を示す入力では24時間経過後の明示解除まで停止 |
| 目標 | 勝利条件を必須入力。作成後は編集不可。期限超過で自動終了しない |
| 達成 | 本人が宣言。AIは審査しない。無料の定型文で必ず負けを認め、追加課題を出さない |
| 取りやめ | 追い打ちなし。履歴を保持し進行中一覧から外す。変更したい目標は取りやめて新規作成 |
| 進捗 | できた・一部できた・できなかった・意図的な休み・体調不良の5区分 + 自由記述。編集不可、削除して再投稿可能 |
| 定型文 | 勝利条件・区分・強度を組み合わせ、同じ文が連続しないようにする |
| 動画の文脈 | 区分と自由記述が食い違えば具体的な記述を優先。曖昧なことは断定しない |
| 長さ | 短い2文、読み上げ約10秒。テキスト・音声・動画は同じ内容 |
| 再生 | すべて手動。音声再生中に動画が完成しても自動で切り替えない |
| 予算 | 日本時間の日次・月次上限。月20ドル、インフラ別枠。日次額は実測後に確定 |
| 予約 | 有料処理の前に見込み費用を確保。残額不足は無料定型文。未課金と確認できない予約は保持 |
| 本数 | 予算が優先。必要なら1日1本等に減らし、成立しなければ動画サービスを再選定 |
| 同時実行 | アプリ全体で動画生成1件、待ち行列なし。生成中も通常投稿は可能 |
| 待機 | 画面は3分で待機終了。バックエンドは継続し、完成後に履歴から手動再生 |
| 復旧 | 受付済みIDがある依頼は状態取得から復旧。受付不明は自動再送しない |
| 結果不明 | 実測に基づくバックエンド打ち切り時間で枠を解放。予約保持、遅延完成は自動表示せず運用確認対象 |
| 非表示 | 停止・強度低下・達成・取りやめで対象の未完成煽りを以後表示しない。再開しても復活させない |
| 削除 | 報告と対応する煽り、さらにその報告を参照した後続煽りを非表示・文脈対象外にする。後続報告と発生済み費用は残す |

## 3. 処理構成

```text
目標作成 / 進捗投稿
  ├─ 通常 → 無料定型テキスト（同期で完結）
  ├─ 停止中 → 挑発のない無料テキスト（記録は継続）
  └─ 動画希望 → 安全判定・生成枠・日次/月次予算予約
       ├─ 利用不可 → 理由を添えた無料定型テキスト
       └─ LLM → 同期テキスト → VOICEVOX → 音声 → Hedra → 動画
                                      └─ R2保存・DB状態永続化
達成 → 外部AIを呼ばず勝利を認める定型テキスト
```

技術方針は Spring Boot + Next.js、PostgreSQL、VOICEVOX、Hedra Character-3、Cloudflare R2、Vercel + Railway を維持する。モデル名・API仕様・価格・依存バージョンは着手時の確認対象であり、旧版の価格やバージョンの断定を実装根拠にしない。

## 4. 初期版の完成条件

| ID | デプロイ環境で確認すること |
|---|---|
| AC1 | 本人だけがログインし、勝利条件付きの目標を作成できる |
| AC2 | 通常投稿は無料定型文、動画希望投稿はテキスト・音声・動画を順次手動利用できる |
| AC3 | 再起動後も受付済みジョブを復旧し、受付不明の依頼を自動再送しない |
| AC4 | 停止・強度低下・達成・取りやめ・削除によって、対象の煽りが後から表示されない |
| AC5 | 日次/月次予算不足時は有料生成を開始せず定型文へ切り替わる |
| AC6 | 達成時は外部AI障害や予算に関係なく、必ずライバルが負けを認める |

実装は [07. 運用とロードマップ](./07-operations.md) の§2.1「S0〜S10」に沿って進める。各ステップの依存関係・成果物・完了条件・進捗表を同章にまとめ、§3に受入テストを定義する。

## 5. 将来の範囲と不採用理由

| 後続・将来 | 初期版で入れない理由 |
|---|---|
| 怒りゲージ・リアクション、3プロバイダ比較画面 | まずコアループを完成させる。比較用の計装と差し替えポートは初期版から持つ |
| キャラクター・声選択UI | 初期版は1体・1音声で体験を調整。データは人格と声を分離 |
| 目標編集、進捗編集 | 過去の宣言と煽りの根拠を保持。将来編集には変更履歴が必要 |
| 達成動画、動画再生成 | 無料で必ず返る勝利を優先。追加課金を避ける |
| OIDC・複数ユーザー・課金・SNS | 本人専用。所有者チェックは初期版から行う |
| 自動煽り・期限通知・Web Push | 本人による投稿・再生を中心にする |
| Live2D・リアルタイム配信、SSE/WebSocket、Redis | 保存して再生できる非同期動画とDB・ポーリングで初期版を構成 |

ユーザー同士の相互煽りは恒久的にスコープ外。将来拡張がすべて無変更・差し替えだけで済むことは保証しない。

## 6. 決定を成立させる実装上の補足

ヒアリングで決めた体験を実装できるよう、各設計書で次の技術契約を具体化した。これらは追加のユーザー機能ではなく、今回の要件を満たす実装方針である。

- 入力参照IDを生成前に記録し、削除と生成完了の競合を防ぐ。
- 動画投入の意図を先にDBへ保存し、外部受付とDB保存の隙間は受付不明として扱う。
- 停止・削除後のアクセスを制御するため、メディア配信時に認可を再確認する。
- 費用台帳と本文を分離し、日/月境界でも未精算予約を解放しない。
