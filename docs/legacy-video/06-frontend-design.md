# 06. フロントエンド設計

> 更新日: 2026-09-08。初期版の画面はコアループ・停止・履歴・予算に集中する。

## 1. 技術と画面

Next.js App Router + React + TypeScript strict、Tailwind、TanStack Query、素のフォームとZodを使用する。API通信型はOpenAPIから生成。画面内の入力はuseState、サーバ状態はQueryで扱う。初期版にZustand、Live2D、WebGL、リアルタイム配信は導入しない。

| ルート | 内容 |
|---|---|
| `/` | 進行中・達成済み・取りやめの目標一覧 |
| `/goals/new` | タイトル・勝利条件・詳細・カテゴリ・期限、動画希望 |
| `/goals/[goalId]` | 宣言・勝利条件・進捗投稿・煽り・手動再生・履歴・達成・取りやめ |
| `/settings` | 弱/標準/強、停止/再開、停止理由・解除可能時刻、日次/月次予算 |
| `/api/proxy/...` | 認証・許可リスト・CSRF対策付きBFF、認可済みメディア取得 |

全画面から停止操作にアクセスできるようにする。怒りゲージ・リアクション・比較グラフ・キャラクター/声選択・目標編集は後続であり、初期版のナビゲーションに出さない。

## 2. 目標作成と進捗投稿

目標には必須の勝利条件を説明付きで表示する（例「参考書を1冊最後まで解く」）。作成後は編集できない旨を説明し、変更は取りやめて新規作成する。期限超過は「期限を過ぎています」と表示するだけで、失敗扱いにしない。

```text
参考書を終える
勝利条件: 参考書を1冊最後まで解く
宣言: 毎日30分取り組む        [達成する] [取りやめる]

進捗区分: できた / 一部できた / できなかった / 意図的な休み / 体調不良
自由記述: [                                     ]
[ ] 動画で煽ってもらう（初期値OFF）
    本日の残り予算 / 今月の残り予算 / 動画利用可否
[報告する]

ライバル: 一歩は進んだな。宣言、忘れてないよな？
[待機画像]  [音声を再生]  [動画を再生]
音声クレジット

履歴: 進捗 [削除] / 煽り / 手動再生 / 目標イベント
```

通常投稿は無料の定型テキスト。動画を選んだときだけ有料生成する。動画利用不可ならチェック不可と理由を表示。通常投稿は利用可能。複数タブ等で状態が変わったときはサーバのvideoDecisionを優先し、保存済み投稿を再送して動画を作ろうとしない。

冪等キーは1回の論理投稿につき1個を作り、ネットワーク再試行中は同じ値を使う。投稿成功まで保持する。再試行ごとに新しいUUIDを作らない。

## 3. 段階表示と待機

| 状態 | 表示 |
|---|---|
| TEXT_ONLY | 定型文で完了。ポーリングなし |
| TEXT_DONE | 本文 + 待機画像、音声生成中 |
| AUDIO_DONE / VIDEO_SUBMITTING / VIDEO_SUBMITTED | 本文 + 音声の手動再生、動画生成中 |
| VIDEO_DONE | 本文 + 動画再生ボタン/ポスター、音声の再生も可能 |
| DEGRADED | 利用可能な上流成果 + 縮退理由 |
| SUBMISSION_UNKNOWN | 「動画の受付状況を確認できません」。再送ボタンなし、上流成果のみ |
| RESULT_UNKNOWN | 「動画の結果を確認できません」。予算確認対象である旨、動画リンクなし |
| SUPPRESSED（表示資格） | 本文・メディアを除去。遅れた取得結果でも復活させない |
| 投稿から3分 | 「完成したら履歴に表示されます」。画面の待機のみ終了 |

TanStack QueryのrefetchIntervalでサーバ指定pollAfterMsを使う。終端・SUPPRESSED・3分で停止。3分の起点はジョブごとの投稿時刻で、別の投稿・再マウントで誤って延長しない。ネットワーク再試行でも表示期限を守る。

3分後はバックエンド生成を止めない。履歴の再取得・画面再訪時に通常完成を表示する。Web Pushや通知音は使わない。動画利用可否は `/me` で再確認し、不明終了で解放された生成枠も反映する。バックエンド打ち切り後の遅延完成は通常履歴に出さない。

## 4. 再生と停止

音声・動画は必ず手動再生。完成通知は画面上の表示のみ。音声再生中に動画が完成しても音声要素を置き換えず、再生を継続する。本人が動画再生を選んだときに音声を停止して二重再生を避ける。

停止/強度低下の操作時はサーバ応答を待たずローカルの全メディアをpauseし、srcを外し、処理中の煽りを隠す。サーバ更新が失敗したら「停止設定を保存できませんでした」と表示し、再生を勝手に再開しない。成功したら設定世代・履歴・ジョブQueryを再取得する。

- 手動停止: 明示再開まで継続。過去の挑発の本文・再生も停止中は抑止。記録確認文と勝利文は表示する。
- 自動停止: 深刻な危険入力で停止。24時間経過後に再開ボタンを有効化し、本人操作が必要。疲労・体調不良だけでは停止表示にしない。
- 強度低下: 変更前の強度で生成中だった煽りを無効化。次の投稿から反映。自動再生成なし。
- 達成/取りやめ: その目標の再生を止め、未完成の煽りを無効化。達成は無料勝利文を表示、取りやめは静かな完了表示。
- 進捗削除: 本文と参照する煽りをQueryキャッシュから除去し、進行中の取得をキャンセル・無効化する。後続報告は残す。

同一ブラウザの別タブにはBroadcastChannel等で停止・無効化を伝える。復帰時・フォーカス時にもサーバを再確認する。別端末の即時停止をポーリングだけで完全保証はしない。サーバ側は操作確定後の新規読み取りを禁止する。

## 5. 履歴・メディア・クレジット

削除済み報告、参照するSUPPRESSED煽りは履歴に出さない。達成・取りやめ前に完成済みの有効な履歴は残す。停止解除で生成途中に無効化した煽りを復活させない。進捗削除時には、関連する煽りも消え、発生済み費用は戻らないことを操作文言で伝える。

メディアは認証済みBFF経由で取得し、サーバで都度資格を検査する。R2直リンクを保存・再利用しない。Cache-Controlはprivate, no-store。取得不可になったらsrcを外し、再取得ループで復活させない。停止前にダウンロード済みのファイルを回収する機能はない。

音声クレジットは生成時のvoiceIdに対応するvoices.credit_textから表示。将来声が変わっても過去の動画の表記を変えない。具体的な話者が未確定の間、仮の実在話者名を利用済みとして掲載しない。

## 6. アクセシビリティと検証

常に本文を併記。読み上げ通知は本文確定時に一度、段階ごとに同じ煽りを連呼しない。キーボードで投稿・再生・停止・削除・達成できる。状態は色だけに頼らず文言でも表示。コントラストとreduced-motionを尊重する。

検証は無料/動画投稿の分岐、任意動画の初期OFF、各状態の表示、3分タイムアウト、手動再生、音声継続、停止の即時pause、遅いレスポンスによる復活防止、削除連鎖、固定冪等キーを中心に行う。
